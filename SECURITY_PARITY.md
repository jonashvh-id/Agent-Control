# Security parity evidence

The pinned reference is Python Phase 2 commit `b946766e705856131b59f386b5ef657310f7dfdf`. The Rust equivalent is exercised against isolated databases/providers; migration does not reuse old keys/data or create new live issues. Tests prove the named scenarios, not immunity to every possible vulnerability.

| Existing invariant / migration boundary | Rust enforcement | Concrete evidence |
|---|---|---|
| Secure human passwords; no default accounts | Argon2id; explicit CLI bootstrap; generic login failures | `security::password_hash_and_verification`, `password_requirements`; isolated CLI validation |
| Current human sessions and expiry | Hashed session lookup, current enabled human | `identity::session_workflow`, `stale_session_rejected`, `disabled_human_session_rejected` |
| Same-origin administrative mutations and CSRF | Origin/Host boundary; current human role and constant-time CSRF | `identity::csrf_required`, `origin_rejected`, `host_rejected`, `host_authority_rejected_on_rest`, `reviewer_cannot_manage_agents` |
| Human-only approval authority | Human session/CSRF; no MCP decision tool or agent role elevation | `identity::agent_cannot_approve`, `human_cookie_cannot_execute_as_agent`, `reviewer_can_decide` |
| Default DENY and explicit ALLOW | Pure typed policy engine; missing policy denies | `governance::default_deny`, `explicit_allow_read`, `policy_scope_intersection_unit` |
| Mandatory GitHub creation approval | Confirmation flag coerces ALLOW to ASK | `governance::creation_allow_still_asks`; both SDK workflows |
| Scoped credentials cannot escalate | Current agent/credential intersection and issuance subset check | `governance::credential_escalation_rejected`, `scopes_cannot_be_overridden_by_allow`; `execution::scope_shrink_after_preparation_blocks_dispatch` |
| Credential, agent, connector and global revocation | Current authorization at every admission and dispatch | `governance::{revoked_credential,disabled_agent,disabled_connector,global_stop}`; `execution::credential_rechecked_after_preparation` |
| Current policy at dispatch | Shared check after durable preparation | `governance::current_policy_deny`; `execution::{policy_rechecked_after_preparation,read_policy_tightened_to_ask_after_preparation}` |
| Exact approval binding | Keyed canonical JSON plus agent/credential/tool/key checks; final fingerprint recheck | `governance::{changed_title_rejected,changed_body_rejected,changed_key_rejected,different_credential_cannot_consume}`; `execution::prepared_request_cannot_change_before_dispatch` |
| Encrypted, authenticated and immutable previews | AES-GCM; separate-purpose key; binding/preview SQL triggers | `security::preview_encryption_authenticated`; `execution::approvals_binding_is_immutable`; `adapter::tests::governance::approved_read_preview_includes_filters_and_rejects_changes`; `governance::preview_encrypted_and_audit_minimized` |
| Expiration and current approver | Conditional consume and final enabled-approver/expiry check | `governance::{approval_expiry_blocks,disabled_approver}`; `execution::{expiry_after_consumption_blocks_dispatch,approver_rechecked_after_consumption}` |
| One-time grants and replay protection | Conditional status transition and unique execution claim | `governance::{exact_approval_executes_and_replay_never_writes,consumed_approval_new_execution_rejected}` |
| Concurrent duplicates and conflicting keys | BEGIN IMMEDIATE; unique agent/key; binding conflict check | `execution::{concurrent_duplicates_dispatch_once,idempotency_conflict}` |
| Durable unknown outcomes and no blind retries | Typed dispatched/uncertain states; recovery; explicit no-retry HTTP client | `execution::{timeout_outcome_is_explicitly_uncertain,untrusted_invalid_provider_response_is_uncertain}`; `security::crash_recovery_marks_unknown_and_preserves_keys`; provider timeout tests |
| Control changes remain available during I/O | Dispatch transaction committed before network | `execution::emergency_stop_does_not_wait_for_network` |
| REST/MCP share authorization | Both invoke the same gateway | `mcp::independent_sdk_discovers_and_executes_governed_tools`; REST governance tests; optional Python SDK workflow |
| Every MCP request rechecks current identity | HTTP guard and callback resolution; stateless transport | `mcp::{forged_session_cannot_restore_revoked_identity,human_cookie_never_authenticates_mcp,duplicate_authorization_header_rejected}`; SDK revocation check |
| Malformed/model-supplied inputs cannot bypass policy | Strict serde wrappers, schema/complexity validation, sanitized protocol errors | `mcp::malformed_mcp_does_not_dispatch`; `security::{malformed_proposals_and_overrides,deep_and_wide_parameters_rejected}`; SDK override rejection |
| Native GitHub permissions remain authoritative | Native 401/403/404 deny regardless of platform grant | `adapter::tests::{native_401,native_403,native_404,governance::actual_adapter_respects_domain_approval_and_native_denial}`; `execution::provider_native_denial_never_retries` |
| Fixed provider origin / no SSRF or deletion | Hard-coded HTTPS origin, no redirects/proxies, finite allowlist, no deletion tool | `adapter::tests::{repository_escape_refused_before_io,redirect_refused,protected_project_and_demo_config_refused}`; `governance::unregistered_delete_rejected` |
| Secure native credentials and rotation | Private regular owned file with O_NOFOLLOW, bounded read, no persistence or client exposure | `adapter::tests::{secret_file_permissions_required,symlink_secret_refused,secret_file_rotation}` |
| Untrusted provider results minimized | Schema/size validation, safe issue URLs/DTOs, result-trust marker; no instruction execution | `adapter::tests::{issue_creation_minimizes_response,url_query_fragment_and_wrong_origin_refused,bounded_provider_response}`; `execution::untrusted_provider_instructions_cannot_dispatch_new_actions` |
| No secrets or raw values in audit/errors | Coarse input summary, known targets only, fixed error codes, minimal receipt | `governance::preview_encrypted_and_audit_minimized`; `execution::unregistered_agent_tool_names_not_logged`; `identity::malformed_login_does_not_echo_password`; provider error tests |
| Append-only audit and attribution | SQL triggers; identifiers and correlation IDs in shared event writer | `execution::audit_append_only`; HTTP comparison validates execution/approval/agent attribution |
| Resource exhaustion bounded | 32 KiB requests, finite JSON depth/items, deadlines, 4 password workers and 16 provider slots | `identity::{request_limit,password_work_is_bounded}`; `execution::provider_work_bounded_without_blocking_controls`; provider timeout/size tests |
| Fresh isolated persistence, no customer migration | Distinct Rust ownership marker and private single-process lock | `security::{refuses_unowned_python_runtime,runtime_exclusive_lock,symlink_runtime_refused,private_file_reads_bounded}` |
| Existing frontend and Python-independent startup | Same endpoint contracts; embedded assets and standalone executable | `identity::frontend_and_admin_compatibility`; `standalone::copied_executable_starts_without_python_or_workspace`; browser/CLI validation |

Tests are located in `crates/server/tests`, `crates/control-core/tests/security.rs` and `crates/connector-github/src/adapter/tests.rs` and `adapter/tests/governance.rs`. Module and source/destination details are in [RUST_MODULE_MAP.md](RUST_MODULE_MAP.md) and [RUST_MIGRATION_REPORT.md](RUST_MIGRATION_REPORT.md). Actual command results and coverage limits are in [MIGRATION_VALIDATION.md](MIGRATION_VALIDATION.md).

The Rust implementation strengthens explicit uncertainty/state transitions, single-process recovery, library-backed memory handling and bounded concurrent work. Authentication/token/preview storage formats differ because Rust uses new isolated data. No live legacy migration is claimed. Local database operators, admitted-I/O cancellation, managed vaults, tenant isolation, external audit integrity, SSO/MFA and MCP OAuth retain the limitations documented in SECURITY_BOUNDARIES.md.

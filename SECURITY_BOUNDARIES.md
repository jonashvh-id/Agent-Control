# Security boundaries — Rust foundation

Humans authenticate through Argon2id passwords and private hashed sessions. HttpOnly/SameSite cookies, HTTPS secure-cookie configuration, same-origin login and constant-time CSRF verification protect administrative mutations. All routes require the configured Host authority, including its port; URL components in Host are rejected. Agents use separate scoped credentials whose keyed hashes are stored in SQLite. Human cookies and MCP transport state cannot confer agent access; agent tokens cannot confer human roles.

Every MCP request revalidates the current credential and active agent. Discovery, admission and final dispatch use one current-authorization path: identity, scope intersection, policy, connector state, global stop and execution enablement. Tools default DENY. GitHub creation forces ASK; repository deletion has no executable capability. REST follows the same gateway.

Immutable approvals bind agent/credential/tool/connector, keyed exact-parameter fingerprints and idempotency keys. Previews use authenticated AES-GCM with separate-purpose key material and are exposed only to authenticated humans. Current approval status, expiration and enabled approver are checked at consumption and dispatch.

The SQLite ledger durably records claims and dispatch before I/O. Unique keys and conditional state transitions prevent concurrent duplicate dispatch. Uncertain or failed claims are never automatically retried; recovery preserves uncertain state. Already admitted calls can finish after revocation. No exactly-once or cancellation guarantee is made.

GitHub uses a fixed HTTPS origin, finite allowlists, native permissions, no redirects/proxies/retries, bounded responses/time and safe minimal DTOs/receipts. Private owned nonsymlink credentials are reread at dispatch and never given to agents. No CLI/keychain credential import path is supported; the GitHub adapter uses an explicitly configured private credential file.

Runtime paths require a distinct Rust ownership marker and private Unix files; another process cannot open the same runtime. Existing Python/customer directories are rejected. Fresh SQLx migrations do not migrate live data. Database operators remain trusted: local append-only/immutable triggers are not an external tamper-proof audit system.

Google Drive is an independent fixed-origin adapter. Search filters names from at most 20 configured file IDs; read accepts only those exact IDs and returns at most 6,000 characters from Google Docs or plain text. Native API responses are limited to 256 KiB; unsupported types, native 401/403/404, redirects and invalid content are refused. No share/edit/delete capability exists. Google credentials are private short-lived access tokens, reread for each native request, never passed to the agent. Integrated Google OAuth/refresh is not implemented. A `drive.readonly` token can have broader native access than the gateway allowlist; use a dedicated identity with narrow native resource access where possible.

Human-only catalog/access diagnostics are presentation, not authorization. Scoped credentials do not gain scopes when their agent’s assigned capabilities increase; current scope intersection still applies. Actor display names are joined when the authorized human reads audit/approvals, without adding names or raw values to stored audit payloads. Codex connection snippets reference an environment variable and never embed credentials.

Input/body/JSON-complexity/result sizes, request/provider deadlines and password/provider concurrency are bounded. Errors omit inputs/provider exception text; audit retains actor/correlation identifiers, policy decisions, keyed fingerprints and minimal receipts, without raw arguments or arbitrary results. Unknown agent-supplied tool names are omitted. Provider content remains untrusted data and cannot dispatch actions.

Only connections routed through this platform are controlled. MCP OAuth, SSO/MFA, managed vaults, tenancy, external audit integrity, reconciliation/cancellation and production security/load certification remain future work. MFA, managed secrets and an independent review are prerequisites before client deployment. Validation is performed by the implementer, not an independent auditor.

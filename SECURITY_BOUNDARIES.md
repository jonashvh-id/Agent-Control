# Security boundaries — Rust foundation

Humans authenticate through Argon2id passwords and private hashed sessions. HttpOnly/SameSite cookies, HTTPS secure-cookie configuration, same-origin login and constant-time CSRF verification protect administrative mutations. All routes require the configured Host authority, including its port; URL components in Host are rejected. Agents use separate scoped credentials whose keyed hashes are stored in SQLite. Human cookies and MCP transport state cannot confer agent access; agent tokens cannot confer human roles.

Every MCP request revalidates the current credential and active agent. Discovery, admission and final dispatch use one current-authorization path: identity, scope intersection, policy, connector state, global stop and execution enablement. Tools default DENY. GitHub creation forces ASK; repository deletion has no executable capability. REST follows the same gateway.

Immutable approvals bind agent/credential/tool/connector, keyed exact-parameter fingerprints and idempotency keys. Previews use authenticated AES-GCM with separate-purpose key material and are exposed only to authenticated humans. Current approval status, expiration and enabled approver are checked at consumption and dispatch.

The SQLite ledger durably records claims and dispatch before I/O. Unique keys and conditional state transitions prevent concurrent duplicate dispatch. Uncertain or failed claims are never automatically retried; recovery preserves uncertain state. Already admitted calls can finish after revocation. No exactly-once or cancellation guarantee is made.

GitHub uses a fixed HTTPS origin, finite allowlists, native permissions, no redirects/proxies/retries, bounded responses/time and safe minimal DTOs/receipts. Private owned nonsymlink credentials are reread at dispatch and never given to agents. Local gh-demo references an existing credential in memory only for the designated test repository/loopback; native token rights may be broader.

Runtime paths require a distinct Rust ownership marker and private Unix files; another process cannot open the same runtime. Existing Python/customer directories are rejected. Fresh SQLx migrations do not migrate live data. Database operators remain trusted: local append-only/immutable triggers are not an external tamper-proof audit system.

Google Drive remains an independent fixed-origin adapter. Integrated OAuth uses the maintained oauth2 library with S256 PKCE, one-use state and a short-lived HttpOnly/Lax callback cookie bound to the original administrator session. The ordinary human cookie remains Strict; the callback independently validates the original session, current enabled administrator, issuer when returned, client and expiry. Session authority is checked again after external exchange before storing credentials. Google codes, verifier and native tokens do not enter audit or the agent environment. Tokens and metadata are authenticated-encrypted under separate-purpose keys with row-specific associated data; refresh is serialized, scope enlargement is refused and invalid grants erase credentials/disable the connector. This local encrypted store is not a managed vault.

Managed Drive requires an enabled explicitly granted folder and the stricter resource/tool policy at admission and dispatch. Exact approval binds `resource_id`, file/folder IDs and bounds. Native inventory checks reject broader/incomplete visibility and require non-editable selected folders; content/search membership is rechecked through current parent chains, with bounded depth/page limits and no shortcuts. Other configured nested roots (including disabled roots) cannot be traversed using a parent grant. Native requests are fixed-origin, without redirects/proxies/retries, bounded to 256 KiB; only bounded Docs/plain-text reads and metadata searches are exposed. Search is direct-child navigation, not an unbounded crawl.

The readonly OAuth scope does not itself limit folders. Use a dedicated native Reader identity whose sharing is restricted to intended folders. Native inventory is a snapshot of listed accessible objects and reported folder capabilities, not an exhaustive ACL certification. Public/link-discoverable objects, provider changes between checks, and already admitted calls are not a guarantee of cancellation. Agent Control resource disable/disconnect blocks new platform access; it cannot remove native shares with a readonly scope. Revocation is attempted with Google after local removal; unsuccessful native revocation is reported. Compatibility file-token mode remains separate, with explicit configured file IDs and no integrated refresh; it is mutually exclusive with managed OAuth.

Minimal audit contains trusted resource UUIDs and keyed object references. Names/native IDs are encrypted separately and projected only to authorized human views; document text and native errors/results are excluded. Projections show latest stored metadata, not historical snapshots of every name. Admin-only Operations distinguishes current credentials/recent requests from online presence. Reviewers can read the existing audit/approval surfaces but cannot administer native connections/resources.

Human-only catalog/access diagnostics are presentation, not authorization. Scoped credentials do not gain scopes when their agent’s assigned capabilities increase; current scope intersection still applies. Actor display names are joined when the authorized human reads audit/approvals, without adding names or raw values to stored audit payloads. Codex connection snippets reference an environment variable and never embed credentials.

Input/body/JSON-complexity/result sizes, request/provider deadlines and password/provider concurrency are bounded. Errors omit inputs/provider exception text; audit retains actor/correlation identifiers, policy decisions, keyed fingerprints and minimal receipts, without raw arguments or arbitrary results. Unknown agent-supplied tool names are omitted. Provider content remains untrusted data and cannot dispatch actions.

Only connections routed through this platform are controlled. MCP OAuth, SSO/MFA, managed vaults, tenancy, external audit integrity, reconciliation/cancellation and production security/load certification remain future work. MFA, managed secrets and an independent review are prerequisites before client deployment. Validation is performed by the implementer, not an independent auditor.
